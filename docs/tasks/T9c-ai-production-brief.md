## Why
The production team makes videos with generative AI. Every proposal must say whether an ORIGINAL piece inspired by the item could be made with AI, how, and what blocks it (rights, real people's likeness). The Claude leader reviews this claim, so it must be visible in `hunter.leader show`.

## Shared contract (ALREADY in the repo, written by the orchestrator, do not edit)
`backend/hunter/models/briefs.py`: `FocusTag`, `AIFeasibility` (`CAO` / `TRUNG_BINH` / `THAP`), `AIProduction(feasibility, approach_vi, constraints_vi: list ≥1)`; `BriefContent.focus_tags: list[FocusTag] = []` and `BriefContent.ai_production: AIProduction | None = None`; `ScoringResult.focus_tags`. Both fields default so every stored brief still loads. `focus_tags` is CODE-OWNED (copied from `ScoringResult.focus_tags`; the AI can never set or override it, exactly like the other code-owned fields).

## Work
1. **Drafter output.** Add a required object `ai_production` to the JSON schema and the instruction text in `prompts.py`: `{"feasibility": "CAO"|"TRUNG_BINH"|"THAP", "approach_vi": string, "constraints_vi": [string, …]}`. The drafter builds `AIProduction` from it. Validation (same retry-once path that already handles missing `why_notable` labels; after the retry still invalid → raise like today): feasibility is one of the three values; `approach_vi` has 15–80 whitespace-delimited words; `constraints_vi` has ≥1 non-empty entries. `focus_tags` is set from `scores.focus_tags` (code-owned). A revision pass must keep both.
2. **Prompt rules (Vietnamese, add to the numbered rules in `prompts.py`, keep the existing prompt-injection guard):**
   - `feasibility = CAO` only if an ORIGINAL piece can be made entirely with generative AI tools without real people and without copyrighted characters/episodes: animation or illustration, narrated stories with an AI voice, explainers, imaginary micro-drama with invented characters. `TRUNG_BINH`: only part can be AI, or heavy manual editing/research is needed. `THAP`: depends on real people, live events (sport scores, breaking news), sensitive subjects, or protected IP, or there is no sensible AI approach.
   - `approach_vi`: say HOW at the level of tool CLASSES (image generation, image-to-video, text-to-video, AI voice, AI music, automatic editing) and what the original piece would look like, inspired by the FORMAT or STRUCTURE only. Never promise quality or results; never name a specific paid product as a requirement; no complete script (out of product scope, `idead.md` §2).
   - `constraints_vi`: at least one entry: rights/trademark of the source work, likeness or voice of real people, the label "nội dung tạo bởi AI" where a platform requires it, facts that still need checking.
   - NEVER propose recreating a real person's face or voice, copying a copyrighted character, scene or episode, or making a video that could make viewers believe it is real footage. If the item is about a real person or a protected work, `feasibility` must be `THAP` or `TRUNG_BINH` and `constraints_vi` must say why.
3. **Exports.** `render.py`: the Markdown gets a section `## Khả năng làm bằng AI` (feasibility label in Vietnamese: CAO → "Cao", TRUNG_BINH → "Trung bình", THAP → "Thấp"; approach; constraints as bullets) and a line with the Vietnamese focus-tag labels (`phim_ngan` "Phim ngắn", `micro_drama` "Micro-drama", `giai_tri` "Giải trí", `ai_san_xuat` "Sản xuất bằng AI"). When `ai_production` is `None` (old briefs) print "Chưa đánh giá khả năng làm bằng AI." The JSON export already serialises the model; assert it contains both fields.
4. **Telegram handoff** (`messages.py` `format_handoff`): add one line `Làm bằng AI: <Cao|Trung bình|Thấp> — <approach_vi>` and the focus labels, keeping the message within the existing length handling (truncate the approach, never the mandatory lines). Do not change the P1 alert format.
5. **Leader CLI** (`leader/__main__.py` `show`): include `focus_tags` and `ai_production` in the printed fields so the Claude leader can review them.
6. **Inbox filters.** `GET /briefs/inbox` accepts optional query parameters `ai_feasibility` (`CAO|TRUNG_BINH|THAP`) and `focus_tag` (one `FocusTag`); both combine with the existing filters by AND; unknown values → 422 with the existing redacting handler. Implement in `services/inbox.py` with SQLite `json_extract` / `json_each` on `content_json` (no schema migration). Old briefs without the fields never match a feasibility filter and never match a focus filter.
7. **API docs.** Update `docs/API.md` (the new fields and the two query parameters). Regenerate `docs/openapi.json` with the command at the end of `docs/API.md` (run from the `backend` directory, UTF-8, LF) — the OpenAPI test compares paths and security with the live app.
8. **Tests.** Drafter: valid `ai_production` accepted; each invalid case (bad enum, 14 and 81 words, empty constraints, missing object) triggers the retry path and then fails; `focus_tags` come from `ScoringResult` and an AI attempt to supply `focus_tags` is ignored; revision keeps both fields; the prompt text contains the NEVER rules and the instruction to describe tool classes (assert on key phrases). Render: Markdown section and labels, `None` case. Telegram: new line present, length cap respected. Leader `show` prints both fields.
