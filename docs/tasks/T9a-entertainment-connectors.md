# T9a — Connectors for short film / micro-drama / entertainment signals (Codex)

> **MANDATORY: read `AGENTS.md` and `docs/tasks/_COMMON-RULES.md` first.** Zero extra cost applies: only free public endpoints that need NO key, NO account, NO card. Your sandbox has no network: test with fakes and the captured fixtures below.

## Why
The product owner found no short-film / micro-drama / entertainment content in the Inbox, and wants proposals oriented to content that can be made with generative AI (`idead.md` §3 groups 3 and 6). The three connectors we have (Hacker News top stories, Google Trends VN, Wikipedia top views) do not look for these topics. Real signals exist on free public sources (verified by the orchestrator on 2026-11-22): Hacker News carries stories such as "The Rise of Microdramas" (BBC) and "AI generated over 95% of China's new microdramas in Q1 2026" (CNA); Vietnamese news sites publish entertainment RSS.

## Work
1. `vn_entertainment_rss.py` — class `VnEntertainmentRSSConnector(PublicConnector)`, `id = "vn_entertainment_rss"`, capability `BROAD_DISCOVERY`. ONE connector, ONE saved source, THREE feeds (the table). Follow `google_trends_vn.py` for structure. For every feed item produce a `RawItem`: `source_url` = the article link (canonical https URL, drop tracking query strings only if the existing helpers already do), `external_id` = guid if present else the link, `title`, `published_at` = pubDate converted to UTC, **no metrics** (RSS has none; never invent any), `metadata = {"language": "vi", "category": "giải trí", "publisher": "VnExpress" | "Tuổi Trẻ" | "Thanh Niên", "description": <plain text of the description: HTML tags and entities removed, whitespace collapsed, max 300 characters>}`. One feed failing must NOT discard the items of the others: record the failure the same way other connectors record dropped items/health and raise `ConnectorError` only if ALL feeds failed. Respect `limits.max_items` across the feeds (take items round-robin so one publisher cannot fill the whole batch).
2. `hn_search.py` — class `HackerNewsSearchConnector(PublicConnector)`, `id = "hn_search"`, capabilities `BROAD_DISCOVERY` and `CROSS_MARKET`. Query constants (module level tuple): `"AI short film"`, `"AI generated film"`, `"AI video generation"`, `"text-to-video"`, `"microdrama"`, `"micro drama"`, `"short drama"`, `"AI animation"`, `"AI actors"`. One GET per query, sequential, URL `https://hn.algolia.com/api/v1/search?query=<urlencoded>&tags=story&numericFilters=created_at_i><cutoff>,points>=2&hitsPerPage=20` where cutoff = now minus 7 days (use the injected clock `self._now()`). Parse hits (shape in the fixture): produce a `RawItem` with `source_url = f"https://news.ycombinator.com/item?id={objectID}"` — EXACTLY the format `hacker_news.py` uses, so the same story found by both connectors is deduplicated by the URL fingerprint — `external_id = objectID`, `title`, `creator = author`, `published_at` from `created_at_i`, `metrics = MetricSnapshot(comments=num_comments)` when present, `metadata = {"hn_score": points, "article_url": <public link of url or omitted>, "matched_query": <the query>}`. Deduplicate by objectID inside the batch (keep the first query that matched). Skip hits without a title. A failed query must not discard the other queries' items (same rule as above); raise only if all queries failed. Respect `limits.max_items` and send NO request when the batch is already full.
3. `registry.py`: register both factories; `default_sources()` gains: `SourceInput(connector_id="vn_entertainment_rss", name="Báo giải trí Việt Nam (VnExpress, Tuổi Trẻ, Thanh Niên)", platform="vn_news", url="https://vnexpress.net/rss/giai-tri.rss")` and `SourceInput(connector_id="hn_search", name="Hacker News — phim ngắn, micro-drama, AI video", platform="hacker_news", url="https://hn.algolia.com/api/v1/search")` (platform `hacker_news` on purpose: same reliability class as the top-stories source). Check `runtime seed-sources` (`backend/hunter/runtime/__main__.py`, read-only for you) stays idempotent and report if it needs a change.
4. Tests (`test_connectors_entertainment.py`, fake transport only, no network — copy the pattern of `test_connectors_sources.py`): each RSS fixture parses (title, UTC `published_at`, no metrics, `metadata` keys, description stripped of HTML and ≤300 chars); one feed failing keeps the others; all failing raises; round-robin under a small `max_items`; HN fixture parses; `source_url` format equals the top-stories one; duplicate objectID across two queries kept once with the first query recorded; cutoff and `points>=2` are in the request URL; failed query keeps others; registry lists both; `default_sources()` has the two new entries; connectors send only anonymous HTTPS GETs to the allowed hosts (assert the requested URLs' hosts are only `vnexpress.net`, `tuoitre.vn`, `thanhnien.vn`, `hn.algolia.com`).
