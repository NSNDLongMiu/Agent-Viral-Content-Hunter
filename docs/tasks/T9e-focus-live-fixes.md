## What the orchestrator measured live (2026-11-22, 211 real items from 5 connectors)
1. **Feed label counted as content.** The VnExpress entertainment feed sets `metadata["category"] = "giải trí"`; the relevance corpus includes `category`, so **60 of 60** items got the `giai_tri` tag and +25, including "Mốt trench coat siêu ngắn" (a fashion item) and "Ẩm thực mẹ làm" (a cooking item). The tag must come from the item's own title/description, not from the feed's label.
2. **`ai_san_xuat` false positives.** Weak keywords `ai-generated`, `ai generated`, `ai voice`, `ai music`, `ai avatar`, `ai-made` tagged "Zeus – Claude Code for AI voice agents", "Stop applying to jobs using AI-generated resume", "AquarIum – pick your favorite (AI-generated) fish tank", "ArkViz – AI generated software architecture diagrams". None is about making video/film. Only "HappyWan – … text-to-video creation" is right.
3. **Freshness decay kills on-topic items.** On-topic `hn_search` hits up to 7 days old end with relevance 8.7 (base 70 × 0.5^(age/48h)). A story about AI micro-dramas is still useful days later.
4. **Focus pool starved by Wikipedia.** The pool is ranked by relevance+virality, so 4 Wikipedia pages (virality ~70) took 4 of the 6 focus slots and the entertainment news got 2. Also the generic (non-focus) pool selected noise ("Deaths in 2026", "lịch âm") on a niche-focused deployment.
5. **Credibility lookup is wrong (existing bug).** `_score_credibility` looks the reliability table up by `source_id` (a UUID string), but the table is keyed by platform names (`wikimedia`, `google_trends`, `hackernews`, `vn_news`…), so every item gets the `unknown` fallback of 35. Also the platform string `hacker_news` is normalized by `extract_platform_key` to `hackernews` (table key) — keep that mapping working.
