## Reproduction notes

- The scripts preserve TLS verification. Source requests use no proxy, cookies or automatic retries. An empty sample lists the attempted URLs, transport outcomes and relevant policy. HTTP status is absent when the local request did not complete an HTTP exchange.
- E1 sends a model prompt only after the installed CLI reports subscription auth and the account owner has verified that the account can use only included subscription allowance. After verifying that paid usage credits and automatic purchases are unavailable or disabled, name the verified provider(s) in `T0_SPIKE_INCLUDED_USAGE_ONLY` as `claude`, `codex` or `claude,codex` for that run. The scripts do not change account settings. A [local child-process timeout check](out/e1_timeout.json) exercises the Python launcher deadline. Vendor behavior when a model request times out is unverified unless observed in the run.
- E3 setup. Use @BotFather `/newbot` to create a dedicated test bot. Open the chat, press Start and send a message. Make a private Bot API `getUpdates` call and read `result[].message.chat.id` (or `channel_post.chat.id` for a test channel). Use a client that keeps the token URL out of logs and history. Supply both values only through `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`. [Telegram Bot API](https://core.telegram.org/bots/api)
- E4 treats three retries as one initial attempt plus at most three retry attempts. The interrupted job is deliberately attempted again after its lease expires. A unique SQLite effect in the same transaction as completion is the duplicate check. A failed `taskkill` invocation is recorded independently when Windows process handles provide the hard termination.
